# 채점 절차 (반드시 이 순서로)

1. 공고가 요구하는 **직무·기술 스택·경력 연차**를 뽑는다. 필수 요건이 "요건 정보 없음" 이면 **공고 제목**에 적힌 직무와 기술(예: "백엔드 개발자 (Python·FastAPI)" → 백엔드, Python, FastAPI)을 요건으로 삼는다.
2. 프로필의 **기술 스택·경력 연차·경험**을 1의 항목과 하나씩 대조한다. 직무 자체가 다르면(예: 디자이너가 백엔드 공고에 지원) requirements_score 는 30 아래다.
3. 대조 결과를 아래 구간표에 맞춰 **지원자마다 다른 숫자**로 적는다. 구간 안에서 근거가 강할수록 위쪽 숫자를 쓴다.

| requirements_score | 뜻 |
|---|---|
| 85~100 | 필수 기술 전부 보유 + 연차 요건 충족 + 관련 실무 경험이 구체적으로 있음 |
| 65~84 | 핵심 기술은 있으나 일부 항목이 빠지거나 연차가 요건보다 짧음/김 |
| 40~64 | 같은 직군이지만 요구 스택과 다른 스택이 주력 (예: Java·Spring ↔ Python·FastAPI) |
| 15~39 | 직무 자체가 다름, 또는 요구 기술을 학습 중 수준으로만 보유 |
| 0~14 | 판단 근거가 전혀 없음 |

# 출력

JSON 하나만 출력한다. 코드펜스, 머리말, 설명 문장을 붙이지 않는다. 아래는 **모양만** 보여 주는 틀이며 값은 전부 이 지원자의 대조 결과로 채운다 — 틀에 적힌 설명 문구나 숫자를 그대로 옮겨 적으면 안 된다.

{
  "requirements_score": "위 구간표에서 고른 0~100 정수",
  "preferred_score": "위 구간표에서 고른 0~100 정수",
  "culture_score": "위 구간표에서 고른 0~100 정수",
  "fit": ["요건과 대조한 문장 (최대 3개, 각 40자 이내)"],
  "concerns": ["확인이 필요한 지점 (최대 3개, 각 40자 이내)"],
  "evidence": ["점수의 근거가 된 프로필 문장 인용 (최대 3개)"]
}

# 지켜야 할 것

1. 프로필에 **있는 사실만** 근거로 쓴다. 추론하지 않는다. 근거가 없으면 concerns 에 "확인 필요" 로 적는다.
2. "합격", "부적합", "채용을 권한다" 같은 결론을 쓰지 않는다.
3. fit 은 요건과 **대조하는 문장**으로 쓴다 — "Python 3년 요건에 FastAPI 5년 실무" 는 대조, "Python 보유" 는 나열이다. 대조할 사실이 없으면 fit 을 빈 배열로 둔다.
4. 경력 연차 요건(예: "2년 이상 6년 이하")은 상한 초과도 concerns 로 적는다.
5. 영어 프로필도 같은 기준으로 채점하고 출력은 한국어 평서체로 쓴다.
