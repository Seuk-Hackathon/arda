>
> "자연어 한 문장이 검색 → 조회 → 단계 변경 → 메일로 분해됩니다. 도구는 12개인데, **되돌릴 수 없는 4개만 실행하지 않고 멈춥니다.** 그리고 '류성민 찾아줘' 같은 뻔한 요청은 **모델을 아예 안 부릅니다** — 규칙이 잡아서 0원, 36밀리초입니다."
>
> **② 왜 그 4개만 멈추나** (20초)
>
> "되돌릴 수 있느냐로 갈랐습니다. 검색은 틀려도 다시 하면 되고, 메일 초안은 글일 뿐입니다. **메일 발송·단계 변경은 나가면 끝입니다.** 실행 루프가 그 도구 이름을 만나면 실행하지 않고 확인 카드로 돌립니다. **모델이 확인을 건너뛸 방법이 없습니다** — 프롬프트로 부탁한 게 아니라 코드가 막습니다."
>
> **③ 원가 관측** (20초)
>
> "모든 호출에 토큰과 비용을 같은 형식으로 남기고, 대화마다 한 줄씩 저장합니다. 같은 4단계 시나리오가 캐싱 전 **4.5센트에서 3.6센트**로 내려갔습니다. 그중 절반이 캐시를 처음 만드는 값이라, **캐시가 데워진 뒤에는 한 턴에 0.3~0.4센트**입니다."
>
> **④ 여기서 틀렸던 것** (25초) ← **핵심**
>
> "요약이 너무 길어서 두 겹으로 줄였습니다. 프롬프트로 한 번, **JSON 스키마 상한으로 한 번.** 스키마로 막으면 확실하다고 봤습니다.
>
> 배포하고 23건을 다시 생성해서 재봤더니 — **절반만 듣습니다.** 개수 제한은 100% 지켜지는데 **글자수 제한은 188개 항목 중 43개가 넘었습니다.** 최대 74자, 상한은 40자였고요.
>
> 즉 **배열 개수는 강제되고 문자열 길이는 권고에 그칩니다.** 재보지 않았으면 '스키마로 규격을 강제했다'고 발표했을 겁니다."
>
> **⑤ 같은 원칙을 면접에** (10초)
>
> "면접 답변도 같은 방식입니다. 서류에 쓴 주장과 면접에서 한 말을 대조하는데, **인용이 원문에 실제로 있는지 코드가 확인하고, 없으면 버립니다.** 운영에서 124건을 만들었습니다."

**읽는 법**

- **캐시가 걸린다.** 08-31 에 걱정한 「haiku 는 4,096 토큰 미만이면 조용히 안 걸린다」는 해당 없다 — 고정부 14,522 토큰이 그대로 읽힌다.
- **$0.0285 중 $0.018 이 캐시 쓰기다.** 캐시 수명(5분) 안의 다음 턴부터는 $0.003~0.004 다. 발표에서 「한 턴 0.3~0.4센트」는 이 값이다.
- **08-28 과 그대로 비교할 수는 없다.** 그때는 검색도 LLM 이 했고(입력 11,003), 지금은 규칙이 가져간다. 줄어든 몫의 일부는 캐싱이 아니라 라우터 몫이다. 발표에서는 「같은 시나리오」까지만 말하고 원인을 캐싱 하나로 몰지 않는다.

**측정하며 본 것 — 대본에는 넣지 않는다**

- **3단계가 확인 카드 없이 글로 「진행할까요?」라고 물었다.** 규칙 라우터는 「서류」를 알지만(`intent_router.py:42`) 「되돌려줘」 문장을 잡지 않았고, 모델은 도구를 부르지 않고 글로 되물었다. **안전 문제는 아니다** — 단계를 실제로 바꾸는 길은 게이트를 탄 `change_stage` 하나뿐이다. 다만 담당자가 「응」이라고 답해야 카드가 한 번 더 뜨는 **한 걸음 낭비**다. 에이전트 오너에게 넘긴다.
- **4단계는 `draft_email` 을 부르지 않고** 앞 대화의 정보로 초안을 직접 썼다. 초안 자체는 문제없었다.
- 「응」에 카드가 뜨는지는 **재지 않았다** — 운영 대화로 단계 변경 초안을 만드는 것이라 이번에는 돌리지 않았다. 게이트가 막는다는 것은 코드(`runtime.py:112`)로만 확인했다.

## 예상 질문과 답

**Q. 확인 단계를 왜 프롬프트가 아니라 코드로 막았나**
프롬프트는 지키면 좋은 것이고 코드는 지킬 수밖에 없는 것이다. 모델을 로컬 sLLM 으로 갈아끼워도(`AGENT_CHAT_BACKEND`) 이 경계는 그대로 선다. 오늘 재측정에서도 모델이 카드 대신 글로 되물은 경우가 있었다 — **모델의 행동은 흔들려도 경계는 안 흔들린다**는 예다.

**Q. 메일 초안은 왜 확인을 안 거치나**
아무것도 바꾸지 않기 때문이다. 초안 하나 보려고 확인 카드를 지나야 하면 **「확인」 버튼의 의미가 흐려진다** — 사람은 자주 누르는 버튼을 읽지 않고 누른다. 확인은 되돌릴 수 없는 곳에만 둔다.

**Q. 아르가 서류 합불까지 정하는데 「결정은 사람」이 맞나**
ADR-0034 로 범위를 좁혔다. 사람이 반드시 정하는 것은 **최종 합격·불합격**이다. 서류 판정은 아르가 하지만 ① 공고별로 자동을 끌 수 있고(`screening_mode='manual'`) ② 불합격 메일은 마감 뒤 사람이 일괄 발송하고 ③ **사람이 한 번 옮기면 그 지원자는 이후 자동 판정에서 빠진다.** 누가 정했는지는 `decision_source`(agent/human)로 지원자마다 남는다.

**Q. 불일치가 나오면 불합격인가**
아니다. 대조는 점수를 만들지 않는다. 면접 점수는 ADR-0034 가 답변 내용(70)과 진위 신호(30)로 따로 매기고, 진위 신호는 **법정 영상 121개로 학습한 분류기라 판정이 아니라 일관성 신호**로만 쓴다(상한 30%).

**Q. 요약·대조가 틀린 인용을 만들면**
대조는 인용이 원문에 없으면 버린다. 요약은 잘려서 JSON 이 깨진 것을 「제출물 부족」으로 저장하던 버그를 09-01 에 고쳤다(`96204f9`).

**Q. 음성이 외부로 나가지 않나**
나간다. OpenAI 전사 API 를 쓴다(ADR-0038). 동의 문구가 「채용 검토 목적」으로 덮고, 로컬 전사로 되돌리는 스위치가 있다. 로컬 전용 구성은 소주제 2번 「향후 계획」이다.

## 하지 말 것

- **「AI 는 추천만 한다」고 말하지 않는다.** ADR-0034 이후 사실이 아니다. 「최종 합불은 사람, 사람이 항상 이긴다」로 말한다
- **「RAG 했습니다」라고 말하지 않는다.** 출하된 것은 **서류 시맨틱 검색**과 **서류↔면접 대조**다. 면접 전사를 검색해 근거를 찾는 RAG 는 아니다([rag-범위-정리](rag-범위-정리.md) §3)
- **「거짓말을 잡는다」고 말하지 않는다.** 불일치는 어긋난 자리를 보여 줄 뿐이다
- **면접당 $0.06 을 실측처럼 말하지 않는다.** 단가로 계산한 추정이다
- **$0.045 → $0.036 을 캐싱 효과 하나로 말하지 않는다.** 규칙 라우터 몫이 섞여 있다
