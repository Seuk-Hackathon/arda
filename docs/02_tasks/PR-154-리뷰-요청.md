## 왜 팀장이 손대지 않고 넘기나

**두 가지 이유가 겹쳤다.**

1. **도메인 밖 수정이다.** 우정 도메인은 `backend/` (agent 제외)인데 이 PR 은 `mobile/lib/`만 건드린다. `mobile/` 오너는 **민아(minahdev)**. CLAUDE.md 규칙상 남의 폴더를 고쳤으면 커밋 메시지 명시 + 팀 채널 사후 공지가 필요하다. 이 PR 은 그 공지가 있었는지 팀장(수택)이 확인 못 했다.
2. **실기기 검증이 필요한 유형이다.** CI 초록만으로는 부족하다 — 카메라·소켓·프레임 스트림은 안드로이드 실기기에서 실제로 얼굴 프레임이 서버에 도착하는지 봐야 안다.

## 우정에게 확인이 필요한 것

- **왜 우정이 mobile 을 고쳤나?** 얼굴 프레임 미수신은 서버 쪽 로그·데이터(`frames.recv=0`)에서 처음 잡혀서 우정이 원인 추적을 이어간 것으로 추정된다. 맞으면 커밋 메시지·PR 본문에 그 맥락 한 줄 추가하면 좋다 — "서버 로그에서 발견 → 원인 파고 들어가서 앱까지 도달" 정도로.
- **민아와 이야기 됐나?** 이야기 됐다면 그 사실을 PR 본문에 링크·요약해 두자 (팀 채널 링크 등). 안 됐으면 지금이라도 민아에게 넘겨서 실기기 검증을 부탁하는 게 안전하다.
- **팀 채널 공지는 했나?** 안 했으면 지금이라도 짧게 남겨 두자. 4일 방치된 이유는 사후 공지가 없어서일 가능성이 크다.

## 민아에게 필요한 것 (우정이 확인해 준 뒤)

실기기 검증 3가지:
1. **얼굴 프레임이 실제로 서버에 도착하는지** — `frames.recv` 카운터가 0이 아닌지 (서버 로그로 확인)
2. **회전 제거로 다른 회귀는 없는지** — 서버가 방향을 찾는다는 전제(#150)가 실기기에서 실제로 동작하는지, 세로/가로 모드 둘 다
3. **미리보기의 "얼굴 N · 실패 M" 표시가 의도대로 보이는지**

이 3가지가 실기기에서 통과하면 자체 머지 (CI 이미 초록이므로 승인 게이트 없음).
