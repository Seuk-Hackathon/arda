# ADR-0036. SQS 메일 워커 폐기 — n8n 단일 발송 경로로 고정

> **상태**: 확정 · 2026-09-14 · 작성 suvisdev (인프라·총괄).
> 관련: [ADR-0030 n8n 자동화 분리](0030-n8n-알림-자동화-분리.md) · [ADR-0031 AWS 최소화](0031-aws-최소화.md).

## 문제

프로덕션 compose 에 SQS 소비자 워커(`app/shared/worker.py`) 가 계속 떠 있었다. 하지만 `MAIL_DISPATCH=n8n` (ADR-0031 결정) 로 발송 경로가 이미 API → n8n → SMTP 로 넘어간 상태라 이 워커는 **놀고 있었다** — `email_logs` 에 `queued` 행 0건 (2026-09-12 실측 · sent 105 · failed 28).

이 상태에는 두 가지 문제가 있다.

1. **감시 사각지대.** 살아 있는 경로가 아닌 컨테이너는 죽어 있어도 알림이 없다 — 실제로 09-12 인수인계에서 발견될 때까지 `python -m app.worker` (구 경로) 로 재시작 무한루프에 빠져 있었다. 살아 있는 경로가 아니므로 그동안 아무도 못 봤다.
2. **`MAIL_DISPATCH` 기본값의 지뢰.** 코드 기본이 `worker` 였다. 로컬·테스트에서 이 변수를 unset 으로 두면 SQS 어댑터가 붙어 큐에 실린 뒤 아무도 소비하지 않는 조용한 실패가 났다.

## 결정

**1. 프로덕션 compose 에서 워커 서비스를 뺀다.** `infra/docker-compose.prod.yml` 의 `worker:` 블록을 지운다. `restart: unless-stopped` 로 켜져 있던 컨테이너가 다음 배포에 사라진다.

**2. `MAIL_DISPATCH` 기본값을 `n8n` 으로 바꾼다.** unset 상태에서 SQS 로 조용히 실어 놓는 함정 제거. `worker`·`sqs` 둘 중 하나로 명시하면 여전히 SQS 어댑터가 붙는다 — 되돌리기 대비.

**3. 코드는 남긴다.** `app/shared/worker.py` · `SqsMailDispatcher` · 관련 테스트를 그대로 둔다. 이유:
- ADR-0031 은 SES 를 삭제하되 워커를 SMTP 폴백으로 재활용하는 것을 계획했다. 그 재작성은 별도 커밋이다.
- n8n 이 잠깐 멈춰도 큐를 켜서 발송을 이어갈 수 있어야 한다는 요구가 아직 있다. 코드가 있으면 compose 에 서비스 한 블록만 되살려 스위치.

## 배제한 대안

**전부 삭제 (코드·테스트 포함).** 폴백 여지를 완전히 없앤다는 뜻이 되고, 팀 논의 없이 결정할 크기가 아니다. n8n 이 죽었을 때 대응이 없다. **기각.**

**compose 만 두고 코드 유지, 기본값도 그대로.** unset 지뢰가 남는다. 로컬 테스트에서 계속 SQS 로 실어 놓고 이유를 못 찾는 케이스가 재발한다. **기각.**

## 결과·확인

- **되돌리기**: 이 파일 커밋의 git blame 을 보면 옛 워커 서비스 블록이 남아 있다. 그 15줄을 compose 에 되살리고 `.env` 의 `MAIL_DISPATCH=worker` 로 두면 원상 복구.
- **테스트**: `test_default_uses_n8n_dispatcher` · `test_worker_env_uses_sqs_dispatcher` · `test_switch_selects_adapter` 가 세 경로를 모두 검증한다.
- **다음 후속**:
  - 워커 코드를 SMTP 폴백으로 재작성 (ADR-0031 §「워커는 SMTP 20줄로 비상 폴백만」) — 지금은 SES 만 쓴다.
  - `SqsMailDispatcher` 는 SES 삭제 시점(리허설 후)에 함께 삭제 검토.
