# ADR-0038. 실시간 면접 전사 — 프로덕션 기본을 OpenAI API 로

> **상태**: 확정 · 2026-09-15 · 작성 suvisdev (인프라·총괄).
> 개정 대상: [ADR-0032 추론 모델 3종 확정](0032-추론-모델-3종-확정.md) 의 "전사 = faster-whisper large-v3-turbo(비용 0)" — 실시간 경로의 **프로덕션 기본**만 바꾼다. 로컬 경로는 남긴다.
> 관련: [07-deploy STT 절](../00_overview/07-deploy.md) · `ai/lie-detection/interview_ws.py` · `backend/app/agent/stt.py`.

## 문제

2026-09-15 앱 실기기 면접(세션 75, 토큰 `ORjRSr4K`)에서 답변이 저장되지 않았다. 실측:

| 사실 | 값 |
|---|---|
| 1번 답변 발화 | 43.9초 |
| 전사 시간 | **180초 상한 초과 → 포기** → DB 에 `[전사 지연 · 발화 43.9초]` 저장 |
| 뒤 답변들 | 상한 시계가 **줄 서서 기다린 시간까지 세서**(`전사 대기 153.9초` → 26초 뒤 "180초 초과") 연쇄로 자리표시자·409 |
| 서버 | t3.large 2 vCPU · lie-detection 컨테이너 CPU 115% · 얼굴 판정 114회 전부 실패하면서도 CPU 소모 · "이상입니다" 확인용 4초 전사가 같은 코어를 나눠 씀 |
| 09-11 로컬 벤치 | 30초 발화 37초(0.8배속) — 운영에서는 경합 때문에 그보다 훨씬 느렸다 |

지원자가 1번이 안 넘어가니 [답변 완료] 를 연타해 2~4번이 6초 간격으로 빈 답변으로 소진됐다(`by_button: 6`). 전사 지연이 원인, 빈 답변은 결과다.

## 결정

1. **실시간 전사의 프로덕션 기본을 OpenAI 전사 API 로 한다.** lie-detection 이 backend/.env 의 `STT_BACKEND` · `OPENAI_API_KEY` · `WHISPER_MODEL` 을 그대로 읽는다 — "오디오가 밖으로 나가는가" 는 변수 하나로 한 번만 정한다. 백엔드의 업로드 답변 경로(`session_service.py`)는 이미 같은 API 를 쓰고 있었다.
2. **"이상입니다" 끝 확인**(`says_done`)도 API 로 한다 — 끝부분 4초라 1초 안팎. 로컬 모델을 CPU 에 물고 있지 않아도 된다.
3. **줄에 서지 않는다.** API 호출은 CPU 를 안 쓰므로 `_stt_running`(한 번에 하나) 밖에서 돈다. 여러 답변이 겹쳐도 서로 느려지지 않는다.
4. **로컬 경로는 남긴다.** `STT_BACKEND` 를 비우거나 `faster_whisper` 로 두면 `STT_MODEL` 로컬 전사. 둘 다 켜 두면 API 실패(망·한도·5xx) 시 로컬로 물러선다. 로컬도 없으면 `[전사 불가 · …]` 자리표시자 — 빈 문자열이 아니다(빈 것은 "말이 없었다" 라 답변이 버려진다).
5. 키가 없으면 API 로 **새지 않는다.** 설정과 키가 둘 다 있어야 켜진다.

## 비용 · 리스크

- `whisper-1` 분당 $0.006. 10문항 × 1분 = 면접당 약 $0.06. 끝 확인 4초 × 문항당 몇 번 = 무시할 수준.
- 오디오 외부 전송: 업로드 답변 경로에서 이미 하던 것과 같은 상대·같은 데이터. 동의 문구는 "채용 검토 목적으로만 활용" 으로 이미 덮는다.
- `whisper-1` 은 무음에 말을 지어낼 수 있다. 2026-09-15 개정: 앞단 VAD 게이트는 뺐고(앱 소리를 "목소리 0초" 로 봐서 실제 답변을 튕김), 대신 `verbose_json` 의 `no_speech_prob` 로 무음에 지어낸 조각을 전사 층에서 거른다(`STT_NO_SPEECH_MAX`, 기본 0.6). 답변 종료는 [답변 완료] 버튼만, 판단은 받아쓴 글 하나로 — PROTOCOL.md 「답변 끝은 [답변 완료] 버튼이 정하고, 답변인지는 전사가 정한다」.
- API 장애: 4번 폴백. 서버 `.env` 에 `STT_MODEL` 을 같이 두면 로컬로 내려앉는다(느리지만 저장은 된다).

## 되돌리기

서버 `backend/.env` 에서 `STT_BACKEND=` 로 비우고 `STT_MODEL=large-v3-turbo` 를 두면 이전과 같다. 코드 변경 없음.

## 남는 일

- 로컬 경로의 상한 시계가 대기 시간을 포함하는 문제(`transcribe_async` 가 세마포어 대기까지 `wait_for` 안에 둠) — 로컬을 다시 기본으로 쓸 때 고친다.
- 얼굴 판정 `no_face 114/114` — 앱이 보내는 프레임에서 얼굴을 못 찾는다. 전사와 별개 문제로 따로 본다.
